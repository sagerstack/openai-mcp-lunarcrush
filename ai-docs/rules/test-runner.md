# Test Runner Rules

## Testing Requirements

### Test Categories
- **Unit Tests**: Test individual functions and methods in isolation
- **Integration Tests**: Test component interactions and integrations
- **E2E Tests**: Test complete workflows from user perspective
- **Live Environment Tests**: Use actual external APIs and real data

### Coverage Standards
- Achieve 100% test coverage as specified
- Test all acceptance criteria from implementation plan
- Include both happy paths and error scenarios
- Test edge cases and boundary conditions

### Test Execution
- Run tests after each implementation change
- Execute full test suite to ensure no regressions
- Generate and analyze coverage reports
- Use actual environment variables for live testing

## Process

1. Analyze task requirements and acceptance criteria
2. Review existing test coverage and identify gaps
3. Write comprehensive test scenarios
4. Validate implementation with tests
5. Report test results and any failures
6. Ensure all AC E2E tests pass exactly as specified in implementation plan
